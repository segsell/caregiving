## Tier C — Configuration tightening  ✅ partially executed

### C1. `.gitignore` additions
See A3 above.

### C2. Stale `per-file-ignores` rows
See B above.

### C3. `pyupgrade --py37-plus` → `--py311-plus`
Bumped to match `pyproject.toml [tool.ruff] target-version = "py311"`,
`setup.cfg python_requires = >=3.10`, and CI matrix (3.11/3.12/3.13).

The bump was applied with diff preview. The rewrites pyupgrade made are pure
PEP 585 / PEP 604 syntax modernizations:

- `Dict[X, Y]` → `dict[X, Y]`
- `List[X]` → `list[X]`
- `Optional[X]` → `X | None`
- `from typing import Callable` → `from collections.abc import Callable`

isort and black then auto-applied small follow-ups (sorting the new
`collections.abc` import; reformatting one specs file). All transformations
are tool-applied, never hand-written. **No logic was changed.**

A side benefit: pyupgrade left `Dict, List, Optional` as unused imports in
some files. They are not flagged because `F401` (unused-imports) is globally
disabled in `pyproject.toml` (Tier-D item #9). When/if F401 is re-enabled,
those will be auto-pruned.

### C4. `interrogate` threshold — DEFERRED
`interrogate --fail-under=40` is permissive. Raising the gate now would force
docstring writing across many files at once and risks rushing them. Leave as-is.

### C5. Extra ruff rule sets — DEFERRED
The repo currently selects `F, E, W, YTT, B, Q, PLE, PLR, PLW, PIE, TID, ISC`.
Useful additions would be `UP` (pyupgrade), `SIM` (simplifications), `RET`
(return checks), `ARG` (unused arguments), `PTH` (pathlib), `NPY` (NumPy),
`PD` (Pandas). Each would generate dozens-to-hundreds of new errors. Enabling
them is a Tier-D scope decision.

### C6. Codespell exclusions — leave alone
The current excludes (German vocabulary in SOEP variable code, sandbox/) are deliberate.

## Tier D — Future work (NOT executed)

Listed for awareness only. Each item touches live source code or design and
should be tackled in a focused, separately-reviewed PR.

1. **Cross-package leaky import** — `post_estimation/` imports
   `caregiving.counterfactual.plotting_utils.ensure_agent_period`. Two files:
   - `src/caregiving/post_estimation/task_plot_labor_supply_transitions_after_care_demand.py`
   - `src/caregiving/post_estimation/publication/task_describe_caregiving.py`

   Suggestion: extract `plotting_utils` (or just the shared symbols) into a
   neutral location like `caregiving/utils/plotting.py`.

2. **Counterfactual task duplication** — 35 `task_*.py` files in
   `src/caregiving/counterfactual/` follow systematic copy-paste patterns
   across counterfactual variants (job_retention, no_care_demand,
   higher_formal_care_costs, full_caregiving_leave_with_job_retention, …).
   Could be consolidated behind a parameterized driver, but this is a
   multi-day refactor that can risk breaking pytask graph reproducibility.

3. **Magic numbers in pension code** — `model/pension_system/early_retirement_paths.py`
   uses literals `67` (line 71) and `2` (line 75) where `model_specs` is
   already in scope. The repo has central age constants in
   `src/caregiving/model/shared.py` — these literals should reference
   `AGE_…` or `model_specs[…]` instead.

4. **`print()` → `logging`** — ~568 `print()` calls in `src/caregiving/`. Many
   are legitimate `task_*` summary outputs; some look like leftover diagnostics
   in non-task modules:
   - `data_management/soep/variables.py` (~30 prints)
   - `estimation/standard_errors.py` (7 prints)
   - `counterfactual/draft_plot_styles.py` (12 prints)
   Triage requires file-by-file judgment.

5. **Type hint coverage is very low.** The ruff config disables ANN001/002/003/201/202.
   Hand-spot-check across `model/`, `estimation/`, `simulation/`, `moments/` shows
   ~99% of public functions lack annotations. Annotating the model core is a
   multi-week project; needs scope agreement before starting.

6. **9 unused pytask markers** ✅ **completed.** Removed in a follow-up commit
   from `[tool.pytask.ini_options.markers]`:
   `check`, `counterfactual_differences_full_caregiving_leave_with_job_retention_vs_baseline`,
   `counterfactual_differences_no_care_demand_vs_baseline`,
   `counterfactual_differences_no_cash_benefits_higher_formal_care_costs`,
   `counterfactual_differences_no_cash_benefits_higher_formal_care_costs_age_profiles`,
   `debugging`, `generate_initial_conditions_10k`, `generate_initial_conditions_1m`,
   `start_params`. All confirmed zero `@pytask.mark.<name>` usages anywhere in
   `src/` or `tests/` on this branch. If an unmerged branch turns out to use
   one, the merge will surface a benign "unknown marker" warning and the
   marker can be re-added.

7. **CI pre-commit coverage** ✅ **already covered.** The
   [pre-commit.ci](https://pre-commit.ci/) GitHub App is installed on the
   repo and auto-runs every hook on PRs without needing any in-repo
   workflow. No action required. (Initial audit missed this because
   `.github/workflows/main.yml` runs pytest only and there is no `ci:`
   block in `.pre-commit-config.yaml` — the App needs neither.)

8. **File-manager duplicate files** ✅ **completed.** Deleted in a follow-up
   commit. Both files were untracked and unreferenced:
   - `docs/POLICY_EXPERIMENTS_CHAPTER_BLUEPRINT (Copy).md` — parallel duplicate
     of the real `docs/POLICY_EXPERIMENTS_CHAPTER_BLUEPRINT.md`.
   - `src/caregiving/counterfactual/plotting_helpers (Copy).py` — Python could
     not import it (filename contains a space, so no `from … import …`
     statement could resolve to it). The 18 importers of `plotting_helpers`
     all resolved to the real `plotting_helpers.py`.

9. **`F401` (unused imports) is globally disabled** in `pyproject.toml`. This
   is unusual; was likely set during the recent refactor to avoid noise.
   Re-enabling later would clean up imports across the codebase.

10. **Type-hint style is inconsistent** where annotations *are* used:
    `np.ndarray` vs `jnp.ndarray` vs `jax.Array`; `Optional[X]` vs `X | None`.
    No fully-annotated module to use as a style reference yet.

## Verification protocol used

After each tier:

- `pre-commit run --all-files` — expect: still passing.
- `pytest -q tests/` — expect: same pass/fail counts as the pre-pass baseline.
- `git diff --stat` — sanity-check the diff matches the intended scope.

If any verification step regressed, the change was reverted before continuing.
